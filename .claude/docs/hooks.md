# Host integration: hooks, output styles, and pre-commit

Cross-cutting detail spanning `hooks/hooks.json` and `output-styles/` at the repo root, `skills/voice-setup/scripts/install_host.py`, and `.pre-commit-hooks.yaml`. Moved out of the root `CLAUDE.md`. Needed only when touching one of those surfaces.

## Where the host integration lives, and which install path gets which half

Two surfaces for one feature, and the split is decided by how the plugin was installed. `output-styles/` and `hooks/hooks.json` at the repository root are auto-discovered by Claude Code when the plugin is enabled, declared in no manifest, and they write nothing into anybody's files. `skills/voice-setup/scripts/install_host.py` is for the install paths with no plugin (a symlink into `~/.claude/skills/`, loose skills), where the only way to reach the same two features is to write into the user's own configuration. `check_plugin_hooks` in `scripts/validate.py` holds the two ends together by comparing the shipped `hooks.json` against `install_host.py`'s `HOOK_SPECS`, so a hook in one and not the other fails the build rather than giving a plugin user and a loose-skill user different behavior.

The uninstall story is entirely `~/.claude/rabbit-writes-host.json`: every path written with the hash it had, every hook command added, and the previous `outputStyle`, which is restored rather than deleted. A second `--install` reads that record forward, because recording the style the first install set as "what was there before" makes the uninstall a no-op that looks like it worked.

## `PreToolUse` cleans a commit or PR message before the shell ever sees it

`claude_hook.py` dispatches three events off one `HANDLERS` table, not three scripts: `on_pre_tool_use` sits beside `on_session_start` and `on_post_tool_use`, matched on `Bash`. It runs on every Bash call, and does nothing (no stdout, exit 0) unless the command contains `git commit` or `gh pr create` and one of `HEREDOC_RX`/`PLAIN_RX` actually finds a `-m`/`--body` argument. This closes [anthropics/claude-code#66504](https://github.com/anthropics/claude-code/issues/66504) at the command level, ahead of and independent from the host's own `attribution` settings key: that key governs the harness's own commit template, and this catches a trailer the model was told to type by its base prompt regardless of what that key is set to.

Two passes run over the message body, in order. `_strip_attribution` drops any line matching `ATTRIBUTION_PATTERNS` (a `Co-Authored-By: ... Claude` line, a `claude.ai`/`code.claude.com` session URL, the emoji PR footer) and collapses the trailing blank lines that leaves behind. `_mechanical_pass` then shells out to `scan.py --apply-safe --stdout --voice auto` over stdin, the same fixer `--apply-safe --write` runs on a file, reading whichever profile `voices.resolve` finds active in the repository the commit runs in. Nothing here calls the model: this is the mechanical, single-answer layer, the same ceiling `--apply-safe` has everywhere else. A word needing judgment (`references/patterns.md`'s carve-out list, an ambiguous swap) is left in the message untouched, same as it would be in a file.

The command is only ever rewritten through `hookSpecificOutput.updatedInput`, and only when the rewrite is provably safe. `HEREDOC_RX` matches `-m "$(cat <<'EOF' ... EOF)"`, this repo's own commit convention and the shape a `Co-Authored-By` line arrives in: a heredoc body is literal shell content between its delimiters, so splicing a cleaned replacement back in cannot break the quoting whatever the replacement contains. `PLAIN_RX` matches a plainly quoted `-m "..."`/`--body '...'`, and is only spliced back in when the cleaned text carries no unescaped copy of the quote character that opened it, since that would close the string early and hand the shell a broken command. Anything else, including a shape this repo's convention never produces, is left alone rather than guessed at. `skills/rabbit-writes/tests/test_claude_hook.py` exercises both shapes, both commands, and the no-op cases (an amend with no message, a non-Bash tool, an unrelated command) that must stay silent.

## Pre-commit hooks are tested from a stranger's working directory

`check_precommit_hooks` in `scripts/validate.py` runs `.pre-commit-hooks.yaml` from a directory that is not this repository, and nothing else in the tree is tested that way. Both suites run from this repository's root with this repository's files by default, which is why two hooks shipped broken: `readme-check` blocked a stranger's commit over this author's semicolon, and `rabbit-scan-voice` handed a plugin-relative `--voice-rules` path to a directory where it does not exist. The check parses `.pre-commit-hooks.yaml` with a regex, so a change to that file's shape makes it fail loudly rather than pass on an empty list.

`check_precommit_hooks` decides whether a hook applies somebody's style rules by reading its own `args` for a `--voice` prefix, which covers `--voice-rules` too. The `args:` guard above it pins that `parse_hooks` read the arguments at all, written against the `args:` key rather than a flag name because the flag has already changed once.

The default hooks apply no voice profile. `readme-check-voice` and `rabbit-scan-voice` are the opt-ins. `rabbit-scan-voice` says `--voice auto` rather than naming a path, so a committer's `.rabbit-voice` wins over the cloned plugin's `ACTIVE`. `resolve_plugin_paths` in `scripts/precommit.py` is no longer needed by anything shipped, and stays for a hand-written `--voice-rules` pointing at a bundled profile. `--no-voice` on `readme_check.py` means "no style profile," not "no prose scan": structure, fingerprints, and craft all still run, because a pasted citation marker is evidence rather than taste.
