# JuliusBrussee/caveman — qualitative note

Caveman's README commits fully to its own bit: the prose itself is periodically written in broken "caveman speak" ("Caveman no make brain smaller. Caveman no phone home."), which is a bold, high-risk formatting choice that works because the tool's entire premise is compressed, blunt language — the README performs the product it's selling. Its best concrete technique is the paired before/after quote table (69-token "normal agent" reply vs. 19-token "caveman agent" reply) shown as literal blockquotes side by side, which demonstrates the value proposition in the reader's own domain (chat replies) before any numbers appear. It's also unusually transparent about limitations: an "honest number warning" callout explicitly states caveman only reduces output tokens, not input, and that savings "can go net-negative" on already-terse workloads — a rare instance of a README arguing against its own headline stat rather than burying the caveat. The independently-measured JetBrains benchmark (8.5% on agentic runs vs. 65% on chat prose) is presented with the discrepancy explained mechanically rather than glossed over, which builds credibility. The heavy use of GitHub alert syntax (`[!TIP]`, `[!NOTE]`, `[!IMPORTANT]`) to call out install tips, caveats, and honesty disclaimers is a clean way to make important asides visually distinct from the main narrative without full section breaks.

**Quotes:**
- "why use many token when few do trick"
- "**Honest number warning.** Caveman only shrinks **output** tokens. Input and reasoning tokens are untouched, and the skill itself adds ~1–1.5k input tokens per turn."
