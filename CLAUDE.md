# rabbit-writes

Claude Code / Codex plugin. Three skills (`rabbit-writes`, `voice-setup`, `readme-writing`) over one prose engine in `skills/rabbit-writes/{references,scripts}`.

## Verify before shipping

```bash
python3 scripts/validate.py                          # manifests, skills, voices, cross-refs, tripwires
python3 skills/rabbit-writes/tests/run.py            # engine, voice, verifier, fixer, invariants
python3 skills/readme-writing/tests/run.py           # structure, links, voice, 100-repo regression
python3 scripts/detector-corpus/test_corpus_harness.py   # the corpus harness, network stubbed
python3 scripts/voice-eval/test_eval_harness.py          # the reconstruction scorer, over stubbed triples
claude plugin validate .                             # marketplace manifest only, and it never reads $schema
```

The engine suite runs about 2:20 now, past a 120-second command timeout, so background it or raise the limit rather than watching it get killed. `run.py -k <substring>` while iterating: the corpus-wide tests in `test_verify.py` and `test_stylometry.py` are most of the wall clock, and everything else finishes in seconds.

`run.py` is a stdlib runner so the suite works on a checkout with nothing installed. `pytest` collects the same files and is nicer: run it from inside the tests directory, or from anywhere, since each directory has a `conftest.py` that puts `helpers.py` on the path. `run.py -k <substring>` selects by test or file name.

Tests take zero arguments. `run.py` prints `SKIP` for a test with parameters and then counts it as an error, so a pytest fixture or `parametrize` fails the run rather than degrading to pytest-only. Table-driven cases go in a list inside the test body.

## Where a fact lives

One home per fact. These four moved there and the old copies are gone, so adding a second copy is a regression rather than a style question.

- **Markdown spans, sentence splitting, the lexicon, badge hosts, section keywords, the finding schema.** `skills/rabbit-writes/scripts/rwlib/`. Imported by `scan.py`, `verify.py`, `readme_check.py`, and the corpus research scripts, all of which bootstrap it by inserting the engine's `scripts/` directory into `sys.path`.
- **What kind of document this is, and what slots it has.** `skills/rabbit-writes/references/forms/`, one file per form, each naming the register it routes to.
  There is no third axis: a form *is* a register, which is why the set is a formality spine (`chat`, `informal`, `blog`, `formal`) plus three genre columns (`technical-blog`, `docs`, `linkedin`) carrying tolerances no formality band captures.
  The ladder is data, under the `spine` key, so a rung naming nothing fails `registers.problems` rather than reading as a claim `context.md` makes about the matrix.
  Two names went away for this: casual collided with the voice persona of the same name, and investor-email was a document form posing as a strictness level.
  **A form file supplies slots and only the voice fills them.** A default greeting in `email.md` opens every user's email the same way, which is a shared fingerprint one floor up from the humanizer failure `false-positives.md` describes. `check_form_files` in `validate.py` holds the line by requiring every quoted phrase to sit under `## Tells`, where the heading already says the phrases in it are proscribed. No regex can tell a prescribed phrase from a proscribed one, and a location rule does not have to.
- **The tolerance matrix.** `skills/rabbit-writes/scripts/registers.json`. `scan.py` derives `PROFILE_SKIP`, `PROFILE_RELAX`, `VOCAB_EXEMPT_PROFILES`, and `REGISTERS` from it, and the markdown table in `references/context.md` is rendered from it by `python3 skills/rabbit-writes/scripts/rwlib/registers.py --write`. `validate.py` fails if the doc has drifted.
- **The README corpus figures.** `skills/readme-writing/scripts/corpus_summary.json`, produced from the research aggregate by `scripts/readme-research/05_export_corpus_summary.py`. `validate.py` compares the two whenever `docs/readme-analysis/` is present. It carries `measured_at`, which `04_aggregate.py` derives from the latest `pushed_at` in the sample rather than from the clock, so rerunning the aggregation over the same committed data does not move it. The checker quotes it: "corpus comparison (100 trending repos, 2026-08-10)".
- **Versions.** `lexicon.json` and `registers.json` each carry a `version`. `scan.py --json` echoes both, `PROOF.md`'s heading quotes the lexicon one, and `validate.py` fails if they disagree.
- **How many of an invisible character are in a document.** `rwlib.artifacts.occurrences`. `scan.py` reports off it and `rwlib/fixes.py` thresholds off it, and it is where the emoji-joiner carve-out lives. The two used to count differently, so a document could be reported and then neither fixed nor explained.
- **Which invisible characters exist, and what each one costs.** The tables in `rwlib/artifacts.py`: `HIDDEN_UNICODE` strips, `REPORT_ONLY_UNICODE` never does (bidi in a legitimate RTL document breaks if you strip it), `REPORT_ONLY_TOLERANCE` holds the allowances, and `unlisted_invisibles` backstops all of it with a category sweep. Written as escapes, never literals, and `test_artifacts_source_is_pure_ascii` pins the source file itself because an edit landed literals once while the tables were being written. The Tags block is split with `rwlib/injection.py` by its `tag_runs` threshold: readable runs are the safety band's P0 evidence and never stripped, residue below it strips as `hidden-unicode`, and `fixes.py` enforces the boundary itself so a direct `fixes.apply` call cannot destroy evidence either. Entity spellings count as their characters via `rwlib.markdown.invisible_entities`, minus `&nbsp;`, which is visible and ubiquitous.
- **What a Word document was hiding.** `rwlib/docx_text.py`, stdlib zip and XML only. Visible text goes through the ordinary scan, `w:vanish`/`w:webHidden`/white-`w:color`/tiny-`w:sz` runs are judged with the safety band's own directive rule, and the finding's `line` is the paragraph number. `--apply-safe` refuses the format.
- **How far a document sits from how a person writes.** `rwlib/stylometry.py`. Burrows' Delta over the fixed `MARKER_WORDS` list, with three constants that are the whole calibration: the two sd floors (three samples that agree exactly do not license an infinite z), and `Z_CAP`, which applies to the average and deliberately not to the reported contributors. Uncapped, one paragraph leaning on a marker the author never uses scored z in the thirties and outvoted a hundred markers sitting on the profile. `fingerprint()` computes its own band leave-one-out for the mean and full-set for the sd, because a pure leave-one-out band came out wider than the measurement it calibrates and a foreign register scored in range. Editing `MARKER_WORDS` changes what every stored fingerprint means, which is what `SCHEMA_VERSION` is for, and `distance()` refuses a file from another one rather than comparing against a baseline nobody built. The module takes prose with the markup already stripped: both call sites run `scan.strip_for_stats` first, and a fingerprint built over raw markdown compared against stripped prose reads as a register change because a code fence has no function words in it.
- **Whether a rules file is a profile at all.** `rwlib/voice_check.py`. Two callers, `scripts/validate.py` and `voice-setup/scripts/build_voice.py --check`, so the repository validator and the one that ships with the skill cannot disagree about what valid means. It is structure only: template residue in either file, the mechanic vocabulary (from `voices.MECHANIC_VALUES`, itself assembled from `STRICTNESS` and `NUMERIC_MECHANICS` rather than restated), register names, ban entries naming no term, a `banned_regex` that does not match its own `example`, and a rules file with no markdown beside it. Whether a rule *fires* is a different question and lives in `build_voice.py`, because it needs scan.py. `validate.py` exempts `TEMPLATE` from all of it, since the form is supposed to fail the checks about being a profile.
- **Which voice profile applies, and why.** `rwlib.voices.resolve`: `.rabbit-voice` beside the document or in the working directory, then `voices/ACTIVE`, then nothing, each with the note that says which. There is no fallback to a lone installed profile, and the shipped `voices/ACTIVE` is empty: the plugin ships one example profile, so a fallback meant every fresh install enforcing this author's `default_priority: P0` bans on a stranger's prose with only a note about it. The note now names the `--activate` command instead. This repository keeps its own house voice through a root `.rabbit-voice`, which is the mechanism a consumer uses too. It lived in `readme_check.py` and `scan.py` had none of it, so the two checkers in one plugin could disagree about whose rules were in force. `scan.py --voice auto` and `readme_check.py`'s default both go through it. Resolution is never the default in `scan.py`: that is what the `rabbit-scan` hook runs in somebody else's repository.
- **An HTML character reference.** `rwlib.markdown`. `PROSE_DASH_RX` matches `&mdash;` and `&#8212;` as well as the character, so a find-and-replace cannot walk a document past `verify.py`'s gate or a voice that forbids em dashes. `blank_entities` goes the other way for the semicolon ban, because the `;` closing `&nbsp;` is markup. Both directions are in `tests/test_entities.py`.
- **What priority a synthetic finding is.** `SYNTHETIC_PRIORITIES` in `rwlib/lexicon.py`, beside `SYNTHETIC_FINDING_IDS`. `scan.py` reads it at each call site through `SYNTH = lexicon_mod.synthetic_priority`, so there is no hand-sync left, and an id that is only in one of the two sets raises there rather than drifting. Two tests hold it: `test_every_synthetic_finding_declares_a_priority` on the id sets, `test_scan_raises_each_synthetic_finding_at_its_declared_priority` on the engine agreeing. The one carve-out is `hidden-unicode`, where the table names the P0 ceiling and the space-like half is raised at P2 at the call site.

- **Which fingerprint a register measures against.** `stylometry.path_for(rules_path, register)`, which prefers `<name>.<register>.fingerprint.json` and falls back to the general one. That fallback is silent because almost no profile will ever carry more than one, and `attain.py` prints which file it used precisely because of it: once a register can have its own, "the profile's fingerprint" is no longer one file and two runs are not comparable without knowing. This is the layer where document forms actually diverge. The refusals in a profile carry across forms unchanged, the mechanics carry with the per-register overrides the writer authored, and only the statistical target switches wholesale, because a person's chat register and their essay register are two different objects and their mean is nobody, which is what `per_sample_median` already exists to show. The scope is read off the *filename* by `stylometry.register_of`, since that is what decides which file loads, and the stored `register` key is then checked against it in two places (`check_voices` and `voice_check.check_fingerprint`) because a file renamed by hand measures one register while claiming another. Adding the key did **not** bump `SCHEMA_VERSION`: it is additive and changes nothing about what any stored number means, so a fingerprint written before it is the general one, which is exactly what a missing key says.
- **A fingerprint's measure block, and its sentence shape.** Computed in `rwlib/stylometry.py` (`measure_stats`, `sentence_shape`, `shape_target`, `measure_gaps`), measured nowhere in it. Every number comes from `scan.compute_stats` and `scan.py` imports this module, so the caller passes them in through `fingerprint(..., sample_measures=, sentence_lengths=)`. That is the inversion `distributions(..., split_sentences=None)` already used, and the alternative was a second copy of `compute_stats`. Both arguments are optional, because half the tests and the reconstruction eval build a fingerprint from a bare string, and the empty block is *not* warned about there: it costs nothing until the file is stored, and `rwlib/voice_check.py` fails a stored one outright. The shape is deciles, not raw lengths (which ship the writer's prose verbatim) and not fixed buckets (which turn the edges into a calibration constant). `SCHEMA_VERSION = 2` is what an edit to any of it costs.
- **A number about a document never blocks. A number about an edit may.** `voice-distance` and `voice-caricature` are P2 forever and cannot fail `scan.py --check`, because that is what the `rabbit-scan` hook runs in a stranger's repository over a document nobody asked to convert. `attain.py --check` exits 1 on `flat` and `regressed`, because you ran it on a pair, naming a profile, after asking for a conversion. It ships no pre-commit hook and `check_precommit_hooks` is where that stays true. The two ids in `signature_moves` sit on the document side of that line and are capped at P2 whatever `default_priority` says, because `voice-signature-underuse` is the only finding in the engine that tells an editor to *add* something and a P0 version of it installs a tic.
- **What a number, a date or a quotation is.** `rwlib/facts.py`, and it canonicalizes before it compares, which is the whole design: a `date_format` conversion is *instructed* to reformat a date, so a date compares as ISO, a range is one token, a version is an identifier, and `1,200` and `1200` are one number. Extraction is ordered and each pass eats its span, with dates consumed first and never emitted because `dates()` owns them. The date patterns moved out of `scan.py` (which keeps aliases) because `verify.py` needs them and must not import `scan.py`, which lazily imports `verify`. Five of the carve-outs are there because the 100-README corpus produced a false positive: percent-encoded URL escapes read as percentages, `$1,000` matched only its tail, a sentence-final number was dropped entirely, a spaced em dash between numbers read as a range and fragmented `1,237`, and an HTML attribute value read as somebody's quotation. Entities are report-only forever and never reach `ok`.
- **The manifest `$schema` URLs.** `SCHEMA_URLS` in `scripts/validate.py`, checked against both `.claude-plugin/*.json`. `claude plugin validate` ignores `$schema`, so the marketplace one shipped as a 404 (`claude-code-marketplace-manifest.json`, against the real `claude-code-marketplace.json`) and only an editor would have noticed. Pinned as literals rather than fetched, because CI is offline-safe and the failure worth catching is a typo here.
- **Where `rwlib` is, for something that is not Python.** `pyrightconfig.json` at the root, one execution environment per directory holding a `.py`, each one naming `skills/rabbit-writes/scripts`. Nothing is installed, so a language server has no way to find a package a script puts on `sys.path` at runtime, and `from rwlib import fixes` in a test reads as an unresolved import with nothing wrong with it. `check_import_paths` in `scripts/validate.py` is what keeps the two statements of the same fact together: it reads the bare-name imports out of every file and fails when the config gives that file's directory no path to `rwlib` or to its sibling `helpers`, which is the drift a new script directory causes and whose only symptom is red squiggles in one folder. Local resolution stays the mechanism. `.vscode/` and `.idea/` are gitignored and an editor-specific settings file would not survive a clone. Two things the file cannot say for itself. `typeCheckingMode` is `off` because resolving `rwlib` is what unblocked inference on everything downstream of it: measured over the tree, `off` is 0 errors and 2 warnings, `basic` is 93, `standard` is 95, and 95 inference complaints about untyped stdlib scripts is a type checker nobody adopted rather than a bug list. Unresolved imports are still reported at `off`, so pyright keeps checking the one thing the file exists for. And there is no comment in it and no `$schema`, because pyright validates its own keys and reported both as unrecognized settings on every run, which is what the key list in `check_import_paths` now holds.

- **What makes hidden text an attack.** `rwlib/injection.py`, in the two-axis rule: concealment and a directive in the same span is P0, either one alone is a band lower. `references/injection.md` is the prose form and the only other copy. The band is never fixable (no id in `fixes.py`, and `--apply-safe` refuses the whole run on a safety P0) and never suppressible (`suppress.apply` refuses the `safety` band outright, because a `rabbit-allow` comment lives inside the document an attacker controls). Both refusals are asserted, in `test_fixes.py` and `test_suppress.py`.

## Gotchas

- `validate.py` runs two separate tripwires, and they have different reach. `check_no_stale_skill_name` searches the whole repo for the second prose skill that was merged away before release, exempting only `CHANGELOG.md` and itself. `check_mode_contract` reads one file, `skills/rabbit-writes/SKILL.md`, and pins its mode table, its "a file path tells you where the text lives" line, and the absence of "minimum effective edit" from the guardrail section above `## Modes`. It says nothing about the phrase anywhere else, which is why `README.md` carries it in the attribution list and passes. Rewording either pinned line fails the build on purpose.
- `check_claude_md` in `validate.py` holds the four `CLAUDE.md` files to the code they describe, and only in two ways. A line about registers carrying three or more backticked bare words must name registers from `registers.json` (or modes from its `_modes` block, since the matrix is described in both vocabularies), and a `python3 <path>` line inside a fence must supply the positionals that script's own `add_argument` calls require. Both drifts were live: one file named six registers, four of which do not exist, and showed `verify.py <file>` for a script that takes two paths. A command whose script path does not resolve from the repo root is skipped rather than guessed at, which is what keeps the `cd scripts/readme-research` block quiet. It reads the required-argument counts out of each script rather than from `precommit.py`'s `VALUE_FLAGS`, which is a hook's runtime allowlist and must not be steerable from a doc.
- **Adding or renaming a register is data plus a sweep, and the sweep is all prose.** No register name is load-bearing in engine logic: `scan.py` derives everything from `registers.json`, and `voice_check.py` validates every `mechanics_by_register` key and `applies_to_registers` entry against `registers.registers()`, so a missed rename fails the build rather than silently unhooking a rule. What is *not* caught automatically is the copies in docstrings, test fixtures, and `TEMPLATE.rules.json`, which is why `check_template_registers` now validates the template's own register names (`check_voices` exempts TEMPLATE from `voice_check` and that exemption was covering this too) and fails it for restating the register list in prose, which is how its guidance note came to name four registers that do not exist.
- **Every cell in the matrix is exercised, from a table of trigger documents.** `TRIGGERS` in `tests/test_registers.py` holds one repeatable unit per finding id, and the tests build a document from it: a skip cell must silence a document that fires without it, and a relaxed cell must stay silent *at* its allowance and report past it. Both halves, because a cell that reports at the allowance is strict wearing a tolerance and one that stays silent past it is a skip with an allowance written beside it, which is the confusion that left `curly-quote` unfirable in every register. A coverage test requires `TRIGGERS` to name every id the matrix mentions, so a cell for a new id fails until somebody writes the unit that fires it. A `floor` on a trigger is legal only for an id with no relaxed cell, since a floor would swallow the allowance the relaxed test is measuring, and that is asserted too. This replaced a corpus sweep per register: in-process scanning costs about a second per document per register, so 100 READMEs times a register is minutes for weaker coverage. The corpus number for the one genuinely new register is published in `PROOF.md` instead.
- `validate.py` string-matches `readme_check.py`'s `SCAN_PATH` literal. Change both together or the check degrades to a note instead of a failure. `readme_check.py` also resolves `rwlib` from that same literal, so the two cannot end up pointing at different checkouts.
- Invisible characters are written as escapes everywhere, never as literals. Any tool that normalizes whitespace turns a literal U+00A0 into a plain space, and the check or fixture that depended on it stops working without changing anything a reader can see. This has already happened twice to a test fixture, and both times the literal arrived through a shell heredoc, which passes the character through verbatim while the source line looks correct. After writing a fixture that way, grep the file for codepoints above 127.
- The ASCII rule on engine sources is stricter than the gotcha above says. `test_every_invisible_logic_source_is_escape_only` rejects **any** codepoint over 0x7E in every `.py` it walks, not only the invisible ones: a visible `§` in a comment fails it, which is how it caught one. `markdown.py` is the single exemption, and there the bar drops back to invisible-only, because its regexes spell curly quotes and dashes as themselves. The walk is a list of roots, so a new script directory is not held to the rule until somebody adds it to that list.
- **`verify.validate(...)["ok"]` decides whether `scan.py --apply-safe --write` writes at all.** `run_apply_safe` refuses to write when it is false. A false positive in `verify.py` is therefore not a noisy report: it is a fixer that silently stops working and reports itself as the problem. Anything added to `validate()` inherits that blast radius, which is why the fact check was calibrated over the 100-README corpus before it was wired in, and why `validate(text, fixes.apply(text, None)[0])` over the whole corpus is asserted rather than assumed.
- `PROOF.md` carries two tables whose rows both start `` | `file.md` | ``: the self-scan table and the voice-band table. A regex rewrite of "the row for file X" hits both, and silently replaces the voice-hit counts with stylometrics. Rebuild a table whole, or anchor on its column shape rather than on the filename.
- The corpus research scripts keep their own table patterns and sentence splitter, deliberately. Every committed `stats.json` was measured with those, so swapping in the engine's copies would silently move a published number. The comments at `TABLE_ROW_RE` in `03_analyze_readme.py` say so.
- Scripts resolve siblings by walking up from their own path, so a skill directory can move without editing the scripts inside it.
- The hooks are tested from somebody else's working directory, by `check_precommit_hooks` in `validate.py`, and nothing else in the tree is. Both suites run from this repository root with this repository's files, which is why two hooks shipped broken: `readme-check` blocked a stranger's commit over this author's semicolon, and `rabbit-scan-voice` handed a plugin-relative `--voice-rules` path to a directory where it does not exist. The check parses `.pre-commit-hooks.yaml` with a regex, so a change to that file's shape makes it fail loudly rather than pass on an empty list.
- `check_precommit_hooks` in `validate.py` decides whether a hook applies somebody's style rules by reading its own `args` for a `--voice` prefix, which covers `--voice-rules` too. The `args:` guard above it pins that `parse_hooks` read the arguments at all, and it is written against the `args:` key rather than a flag name because the flag has already changed once.
- The default hooks apply no voice profile, and `readme-check-voice` and `rabbit-scan-voice` are the opt-ins. `rabbit-scan-voice` says `--voice auto` rather than naming a path, so a committer's `.rabbit-voice` wins over the cloned plugin's `ACTIVE`. `resolve_plugin_paths` in `precommit.py` is no longer load-bearing for anything shipped and stays for a hand-written `--voice-rules` pointing at a bundled profile. `--no-voice` on `readme_check.py` means "no style profile", not "no prose scan": structure, fingerprints and craft all still run, because a pasted citation marker is evidence rather than taste. A profile that only fails to *resolve* is a note and the run continues, but a profile named by hand with `--voice-rules` and not readable exits 2, the way `scan.py` does. The alternative was a clean report on a document nobody checked.
- Suppressions live in `rwlib/suppress.py` and are marked, never dropped: a suppressed finding keeps its place in the list with a `suppressed` key, comes out of the priority counts, and is printed under its own heading. `findings.counts` skips it and adds a `suppressed` tally, and both `--check` paths test `"suppressed" not in f`. `scan.scan(..., suppressions=False)` exists for `readme_check.py`, which merges the two halves and runs one pass over the whole list: run in both, the audit would fire twice and call a suppression naming a structure id unused. The repo does not use the mechanism on `references/patterns.md`, on purpose, and `SKILL.md` says why.
- The `safety` band scans raw text and the quoted-example exemption never reaches it, for the reason `citation-leak` opted out: an injection hides in exactly the spans the exemption protects. The cost is P2 `injection-visible-directive` hits on any document that quotes an attack to warn about it, which is why `references/injection.md` publishes 9 of them in `PROOF.md`. The band was calibrated against the 100-README corpus before it was wired to `--check`: 0 P0, 4 P1, 0 P2, and `test_no_corpus_readme_raises_a_safety_p0` asserts the zero rather than reporting it, because a P0 there blocks a stranger's commit. Adding a band means five places, not one: `findings.BANDS`, `scan.BAND_HEADERS` **and** its hardcoded report loop, `readme_check.BAND_TITLES`/`BAND_ORDER` and its loop, and `sarif.BAND_DESCRIPTIONS`. Miss the report loops and the findings count toward `--check` while being invisible in the report.
- `compute_stats` splits paragraphs on blank lines (`scan.py:211`), so a bullet list is one paragraph. `avg paragraph sentences` on a list-heavy document is measuring list length, not prose, and inserting blank lines between bullets moves the number without changing anything a reader sees. Measure the non-list blocks separately before treating that number as a defect.
- `voice-distance` is the one voice finding that is not a rule, and the one that runs without a rules file: a fingerprint is a separate artifact beside the profile and `scan.py` looks for it through `stylometry.path_for`. It is P2 at the call site rather than at the voice's `default_priority`, so a profile that sets `default_priority: P0` cannot promote it, and it is deliberately absent from `fixes.py`. The measurement lands in `stats["voice_distance"]` at every verdict and `json_payload` lifts it to the top level of `--json`, so a rewrite loop can read the before and after without parsing a report and without the number appearing twice in one document. Under `RELIABLE_WORDS` the number is published and no finding is raised off it. `check_voices` in `validate.py` fails a fingerprint with no `.rules.json` beside it, because `scan.py` reaches one only through its profile's rules path and an orphan is never loaded at all: no error, no distance, nothing to notice.
- `citation-leak` and `curly-quote` carry `scan_raw`, so the quoted-example exemption does not reach them. That is why `references/patterns.md` publishes 5 P0s in `PROOF.md`, and why any document that quotes a chat citation marker in backticks fails `--check`. `placeholder` deliberately does not, and its `_scan_raw_note` says why.
- Tests reach an `rwlib` module with `from rwlib import x`, never through `helpers.load_module`. That helper imports a file by path with no parent package, which is right for `scan.py` and `verify.py` and fails for anything under `rwlib/` that imports a sibling: the relative import has no package, and the fallback has no `rwlib/` on `sys.path`. `helpers` puts `scripts/` there for exactly this.
- A ban list entry is escaped whole, so `word_regex` matches a multi-word `banned_words` entry fine. The only real difference between the two lists is that `phrase_regex` lets whitespace flex across a line break. The entry that never fires is one pasted in with its markdown still on it (`` `synergy` ``), because `apply_exemptions` blanks the code span before any ban is applied. That is the case `build_voice.py --check` reports as DEAD, and it is most of why the live-fire probe earns its cost.
- A fresh scaffold fails its own `--check`, on purpose. `build_voice.py --scaffold` strips the template's guidance keys and its `example-rule` entry, and deliberately leaves the `<angle bracket>` prompts in the markdown, because they are the form. The failing check is the to-do list, and `--activate` refuses until somebody fills it in.

## Conventions

- Repo prose is held to the active voice: no em dashes, no semicolons. Check with
  `python3 skills/rabbit-writes/scripts/scan.py <file> --voice-rules skills/rabbit-writes/voices/whit3rabbit.rules.json`
  Two carve-outs, both measured in `skills/rabbit-writes/PROOF.md`. `references/patterns.md`
  is a catalog of the marks it bans and quotes them in before/after examples, so it scores
  25 voice hits on purpose. An attributed quotation is never rewritten anywhere. Everything
  else is at zero and should stay there. `oxford_comma` findings are P2 advisories, not
  defects, and no regex can settle them. The check has a blind spot. An em dash on a list
  line that also carries an inline code span is not reported, while the same dash on a plain
  line is a P0, which is how `voice-setup/SKILL.md` shipped three of them against a voice
  that forbids them. Sweep for codepoints above 127 as well as running the scan, the same
  habit the invisible-character gotcha asks for.
- Dogfood before shipping doc changes: `readme_check.py` on `README.md`, `scan.py` on any `SKILL.md`. Both have found real bugs in themselves this way.
- `skills/rabbit-writes/PROOF.md` publishes measured self-scan numbers. Regenerate it when files move or change, and never just move it. Two traps. Its own row counts its own words, so editing it moves the number you just wrote and you have to iterate to a fixed point. - Calibrate a new detector against `docs/readme-analysis/repos/*/README.md` before wiring it to anything. Those are 100 real third-party documents, and a P0 there is a stranger's blocked commit. Import the module and count: the safety band cost three regexes this way (`instead of editing`, an unanchored agent-noun rule, a bare `forget everything`), each a false positive nobody would have guessed. The corpus is not the whole bar, though. `forget` + a pronoun survived it (the corpus has no `forget your API key` in prose) and was narrowed later to the instruction shape, because in an HTML comment that reads as concealment plus directive and lands a P0 nobody can suppress. Assert the zero in a test rather than reporting it. This is separate from the labeled corpus in `docs/detector-corpus/`, which is still empty.
- **Calibrating a check that compares two documents,** where that corpus is 100 single documents and has no pairs in it. Four passes, and the third carries the trap. Identity: `validate(text, text)` must lose nothing, or a canonicalizer is not idempotent and the bug is in the extractor rather than in the document. Null edit: the same through `fixes.apply`, which is the `--apply-safe` blast radius measured rather than argued about. One generated transform per carve-out, each required to produce zero violations, which is the closest thing to a false-positive rate that exists without paired data. And a planted corruption, required to be caught, because passing the first three is also achievable by a check that never fires. **Apply the reformat transforms outside quoted spans.** Mutating text inside a quotation tests an edit the skill forbids, and protecting quotes by construction makes the result circular. Both mistakes were made here before any of the numbers in `PROOF.md` meant anything.
