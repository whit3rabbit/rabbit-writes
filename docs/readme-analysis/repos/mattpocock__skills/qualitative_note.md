# mattpocock/skills — qualitative note

This README is structured as a persuasive essay rather than a spec sheet: the "Why These Skills Exist" section is organized around four numbered "failure modes" ("The Agent Didn't Do What I Want," "The Agent Is Way Too Verbose," etc.), each opened with a pulled quote from a well-known engineering book (The Pragmatic Programmer, Domain-Driven Design, Extreme Programming Explained) before stating the problem and the specific skill that fixes it. That literary-quote-as-section-epigraph device is distinctive and not something seen in typical tool READMEs, and it lends the argument credibility beyond the author's own authority. The voice is first-person and opinionated throughout ("not vibe coding," "It's hard to explain how powerful this is... Try it, and see"), which is a deliberate departure from neutral third-person documentation tone. A collapsible before/after example ("There's a problem when a lesson inside a section of a course is made 'real'" vs "There's a problem with the materialization cascade") makes an abstract claim about shared vocabulary concrete in two lines. The Reference section's split into "User-invoked" vs "Model-invoked" skills, explained with a one-sentence rule ("A user-invoked skill may invoke model-invoked skills, but never another user-invoked one"), is a clean example of documenting a system's invariant instead of just listing items.
