# DietrichGebert/ponytail — qualitative note

Ponytail's README is built almost entirely around a single sustained metaphor (a laconic, long-tenured senior dev who deletes your code and says nothing), and it commits to that voice in headers, taglines, and even the FAQ ("You don't. Insist anyway and he'll build it. Slowly. Correctly. While looking at you."), which makes an otherwise dry "reduces LOC" pitch memorable and distinctive. Structurally it leads with a concrete before/after code diff (a bloated date-picker wrapper vs. a bare `<input type="date">`) before any numbers, which is a good pattern — show the mechanism, then justify it with data. The benchmark section is unusually self-critical for a README: it explicitly walks back an earlier "80-94% less code" claim as a "conversational-baseline artifact" and links a fuller writeup, which is a rare and credibility-building anti-hype move. The "How it works" section uses a literal numbered decision ladder (YAGNI → reuse → stdlib → native → dependency → one line → minimum) rendered as a code block, turning an abstract design philosophy into something skimmable and quotable. The install section, by contrast, is a long, repetitive per-agent matrix (20+ integrations) that is comprehensive but reads as reference material rather than narrative, diluting the voice established earlier in the doc.

**Quotes:**
- "You know him. Long ponytail. Oval glasses. Has been at the company longer than the version control. You show him fifty lines; he looks at them, says nothing, and replaces them with one."
- "**The rule was never "fewest tokens."** It is: write only what the task needs, and never cut validation, error handling, security, or accessibility."
