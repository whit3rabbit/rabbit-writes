# `scripts/validate.py` internals

Deep detail about the repo's own validator, moved out of the root `CLAUDE.md`. Needed only when adding a check to `validate.py` or debugging why one didn't fire.

**`validate.py` passing proves the repository is valid, and proves nothing about any check in it.** A check that can never fail reads identically from the outside to one that never has, which is how the marketplace `$schema` shipped as a 404 (see below). `scripts/test_validate_checks.py` closes that by copying the tree to a temp directory, repointing `validate.ROOT` and `validate.SKILLS` at the copy, breaking one thing, and requiring the report. The module-level check calls became `CHECKS` plus a `main()` behind an `if __name__` guard, so importing the module does not run the sweep. Two of its cases assert the *absence* of a report (the shipped files pass, and a quoted placeholder slot is allowed), so a neutered check still passes those. That is correct, and it is the reason the other ten exist: mutation-tested, a no-op `check_citation_files` fails nine of the twelve.

**The manifest `$schema` URLs.** `SCHEMA_URLS` in `scripts/validate.py`, checked against both `.claude-plugin/*.json`. `claude plugin validate` ignores `$schema`, so the marketplace one shipped as a 404 (`claude-code-marketplace-manifest.json`, against the real `claude-code-marketplace.json`) and only an editor would have noticed. Pinned as literals rather than fetched, because CI is offline-safe and the failure worth catching is a typo here.

**Two tripwires with different reach.** `check_no_stale_skill_name` searches the whole repo for a second prose skill name that was merged away before release, exempting only `CHANGELOG.md` and itself. `check_mode_contract` reads one file, `skills/rabbit-writes/SKILL.md`, and pins its mode table, its "a file path tells you where the text lives" line, and the absence of "minimum effective edit" from the guardrail section above `## Modes`. It says nothing about that phrase anywhere else, which is why `README.md` carries it in the attribution list and passes. Rewording either pinned line fails the build on purpose.
