# microsoft/markitdown — qualitative note

Unusually, the README puts a security warning ahead of the project description: a `> [!IMPORTANT]` callout about MarkItDown performing I/O "with the privileges of the current process" appears before the reader even learns what the tool converts, and the same warning is elaborated in full later under a dedicated "Security Considerations" section with concrete guidance (use `convert_local()` or `convert_stream()` instead of the permissive `convert()` for untrusted input). This front-loading is a deliberate trade of a slightly slower pitch for correctness/safety-consciousness, appropriate for a library that fetches arbitrary local and remote resources. The "Why Markdown?" section is a good example of justifying a design decision rather than just asserting it, explaining that LLMs are trained on abundant Markdown and that its conventions are token-efficient. Formatting is restrained and functional throughout — short code blocks per install method (pip, source, uv, conda), a comparison table contrasting built-in converters vs. Azure Document Intelligence vs. Azure Content Understanding across four capability rows — with no marketing language, badges limited to three (PyPI version, downloads, "Built by AutoGen Team"), and no emoji or hero image.

**Quotes:**
- "MarkItDown performs I/O with the privileges of the current process. Like open() or requests.get(), it will access resources that the process itself can access."
- "Mainstream LLMs, such as OpenAI's GPT-4o, natively '_speak_' Markdown, and often incorporate Markdown into their responses unprompted." — from the "Why Markdown?" section
