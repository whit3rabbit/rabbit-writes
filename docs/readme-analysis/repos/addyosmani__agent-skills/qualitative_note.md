# addyosmani/agent-skills — qualitative note

This README's standout formatting technique is its ASCII-art pipeline diagram right after the intro (`DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP` with matching slash commands underneath), which instantly communicates the product's mental model before any prose does — a strong example of showing structure visually rather than describing it. It's highly table-driven throughout: a commands table, a full 24-skill catalog broken into six lifecycle-phase tables, a reference-checklist table, an agent-personas table, and a team table, which keeps a large surface area scannable rather than requiring long-form reading. Per-tool installation instructions are consistently tucked into `<details>` accordions (Cursor, Antigravity, Gemini CLI, Windsurf, Codex, etc.), which is a clean pattern for supporting many integrations without overwhelming the main flow — only Claude Code is expanded by default, signaling the primary audience. The "Why Agent Skills?" section name-drops specific engineering concepts (Hyrum's Law, the Beyonce Rule, Chesterton's Fence, trunk-based development) tied to concrete skills, giving credibility through specificity rather than generic claims of quality. It also includes a direct, non-defensive competitive comparison section linking to rival projects (Superpowers, Matt Pocock's skills) and an "honest, side-by-side" comparison doc — an unusually transparent move for a project README.

**Quotes:**
- "AI coding agents default to the shortest path - which often means skipping specs, tests, security reviews, and the practices that make software reliable."
- "Wondering how this stacks up against Superpowers or Matt Pocock's skills? See docs/comparison.md for an honest, side-by-side look..."
