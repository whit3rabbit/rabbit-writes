# rabbit-writes

Core prose engine skill for `rabbit-writes`. Provides detector audits, in-place file deslopping, voice conversions, and drafting.

## Commands

```bash
# Run unit & engine tests
python3 skills/rabbit-writes/tests/run.py

# Run specific tests with filter
python3 skills/rabbit-writes/tests/run.py -k <substring>

# Pytest equivalent (from anywhere)
pytest skills/rabbit-writes/tests/

# Scan prose / audit file
python3 skills/rabbit-writes/scripts/scan.py <file>

# Scan with voice profile rules
python3 skills/rabbit-writes/scripts/scan.py <file> --voice-rules skills/rabbit-writes/voices/whit3rabbit.rules.json

# Check mode gate (exit code 1 on errors)
python3 skills/rabbit-writes/scripts/scan.py <file> --check

# Scan with auto-detected register profile
python3 skills/rabbit-writes/scripts/scan.py <file> --profile auto

# Add the advisory STE vocabulary checks (the counted five are already on)
python3 skills/rabbit-writes/scripts/scan.py <file> --ste

# Silence the STE layer entirely
python3 skills/rabbit-writes/scripts/scan.py <file> --no-ste

# Apply mechanical safe fixes in-place
python3 skills/rabbit-writes/scripts/scan.py <file> --apply-safe --write

# Show what a model would be sent, one passage per finding, and send nothing
python3 skills/rabbit-writes/scripts/scan.py <file> --apply-model --model-plan

# Rewrite those passages through a small OpenAI-compatible model, gating each reply
python3 skills/rabbit-writes/scripts/scan.py <file> --apply-model --model-endpoint http://127.0.0.1:8080/v1 --model-name qwen3-1.7b --write

# Output findings in SARIF 2.1.0 format
python3 skills/rabbit-writes/scripts/scan.py <file> --sarif

# Post-edit integrity check (facts, dates, quotes, numbers). Two files: it
# compares a rewrite against what it was rewritten from.
python3 skills/rabbit-writes/scripts/verify.py <original> <rewritten>

# Measure voice conversion delta between two files
python3 skills/rabbit-writes/scripts/attain.py <source> <target> --voice whit3rabbit
```

## Structure & Architecture

- **`SKILL.md`**: Frontmatter definition and operational guidelines. Defines guardrails and five modes (`detect`, `deslop`, `voice`, `draft`, `ste`). Mode table and guardrails are pinned by repo validator (`scripts/validate.py`). Wording changes there fail the build (see Gotchas).
- **`PROOF.md`**: Measured self-scan numbers and voice-band calibration tables.
- **`scripts/`**:
  - `scan.py`: Main CLI tool and engine scanner.
  - `verify.py`: Integrity and fact-preservation checker.
  - `attain.py`: CLI tool measuring conversion progress and stylometric distance.
  - `lexicon.json`: Machine-writing pattern rules, vocabulary tiers, synthetic-finding priorities.
  - `registers.json`: The tolerance matrix and the only home for register names.
  - `rwlib/`: Shared engine library, holding stylometry, injection checks, fixes, suppression, fact checking, voice resolution, SARIF export, docx text extraction, markdown span/entity handling, the ASD-STE100 layer (`ste.py`), and the model-backed rewriting pair (`endpoint.py`, `rewrite.py`). See "Where a fact lives" below for which file owns which invariant.
- **`voices/`**: Holds active voice marker (`ACTIVE`), voice markdown profiles (`<name>.md`), rule definitions (`<name>.rules.json`), and fingerprints (`<name>.fingerprint.json`). Includes `TEMPLATE` files.
- **`references/`**: Technical and craft reference documentation (`craft.md`, `false-positives.md`, `injection.md`, `patterns.md`, `context.md`, `voice.md`, `checklist.md`, `ste.md`).
- **`references/forms/`**: One file per document form, each naming the register it routes to and the form's slots, length bands, and tells.
- **`references/citations/`**: One file per citation style, checked by `check_citation_files`.
- **`tests/`**: Suite of 20+ test files verifying engine logic, fixes, stylometry, injection rules, and invariants.

## Where a fact lives

One home per fact. Adding a second copy anywhere else is a regression, not a style question.

- **Vocabulary tiers.** `technical_exempt` in `lexicon.json` is the base for every "partial" cell and always applies. A cell may add exactly one further list, named by its "exempt" key. That is how `academic` drops "paradigm" while `technical-blog` keeps flagging it: the shared list would exempt the word in a tech blog too, where a new paradigm for observability is the tier-1 usage the list exists to catch. `registers.vocab_exempt_registers()` returns name-to-list, unioned with `technical_exempt` at one call site in `scan.py`. `problems()` fails four shapes: a cell naming a list the lexicon lacks, a cell restating `technical_exempt`, an "exempt" key on a non-partial cell, and a register whose cells disagree on which list they want.
- **The tolerance matrix.** `registers.json` is the only home for register names. `scan.py` derives `PROFILE_SKIP`, `PROFILE_RELAX`, `VOCAB_EXEMPT_PROFILES`, and `REGISTERS` from it. `references/context.md`'s table renders from it via `python3 scripts/rwlib/registers.py --write`, and `validate.py` fails if the doc drifts. Never restate the register list by hand elsewhere: that's how this same fact once named four registers that don't exist.
- **Which STE checks run unasked.** `MECHANICAL_IDS` in `rwlib/ste.py` (both sentence caps, the paragraph cap, condition order, the semicolon) run in every plain scan. `ADVISORY_IDS`, the six word-list checks, wait for `--ste`. `scan.py`'s `ste=` argument is a tri-state string (`"off"`/`"mechanical"`/`"all"`) that raises on anything else, booleans included: `if ste:` is true for the string `"off"`, which is how `--no-ste` would silently no-op if passed as a bool. Register tolerances drop the first N hits per id in document order before `suppress.apply` runs.
- **The ASD-STE100 word list.** `dictionary_vocabulary` in `ste_lexicon.json`, 719 entries, generated by `scripts/ste-research/` and calibrated against the 100-README corpus. `check_dictionary_vocabulary` raises it under the `ste-vocab` id `check_ai_slop` also uses, but stays a separate function since `check_ai_slop`'s tests pin exact counts against the hand-picked `ai_slop` list. Its regex, `dictionary_vocab_regex`, is hyphen-aware: a plain `\b` boundary matches "cross" inside "cross-platform." Regenerate with the three numbered scripts in `scripts/ste-research/`, run from the repo root. The merge stage only bumps the file's version when the vocabulary content actually changed.
- **What a voice profile may say about STE.** Three mechanics, applied in `scan.py`. `semicolon: allow` stands down `ste-no-punctuation` (it's the writer's sentence shape). `forbid` already reports every occurrence as `voice-semicolon`. `max_paragraph_sentences` stands down `ste-paragraph-sentences` (`voice-paragraph-length` covers the same block). `max_sentence_words`, a `voices.NUMERIC_MECHANICS` entry, replaces the 20/25-word caps in both directions, and the finding's label prints the number in force so a profile's cap never masquerades as the standard's. satoshi carries 35, his measured p95.
- **What counts as one word.** `count_words` in `rwlib/ste.py`. The boundary guards on `NUMBER_WITH_UNIT_RX` are load-bearing: the unit is optional, so without them the pattern matched the digit inside an identifier and `sha256` counted as two words. Every sentence cap reads this number.
- **Versions.** `lexicon.json` and `registers.json` each carry a `version`. `scan.py --json` echoes both, `PROOF.md`'s heading quotes the lexicon one, and `validate.py` fails if they disagree.
- **Invisible-character counting.** `rwlib.artifacts.occurrences` is the one count: `scan.py` reports off it, `rwlib/fixes.py` thresholds off it, and the emoji-joiner carve-out lives there. The two used to count differently, so a document could be reported and then neither fixed nor explained.
- **Which invisible characters exist, and what each costs.** Tables in `rwlib/artifacts.py`: `HIDDEN_UNICODE` strips, `REPORT_ONLY_UNICODE` never does (bidi in a legitimate RTL document breaks if stripped), `REPORT_ONLY_TOLERANCE` holds the allowances, `unlisted_invisibles` backstops with a category sweep. `rwlib/injection.py`'s `tag_runs` threshold splits the Tags block: readable runs are the safety band's P0 evidence and are never stripped. Residue below it strips as `hidden-unicode`, and `fixes.py` enforces that boundary itself. `rwlib.markdown.invisible_entities` counts entity spellings, minus `&nbsp;` (visible, ubiquitous). `rwlib.markdown.PROSE_DASH_RX` matches `&mdash;`/`&#8212;` as well as the character itself, so find-and-replace can't walk a document past `verify.py`'s gate. `blank_entities` goes the other way for the semicolon ban, since the `;` closing `&nbsp;` is markup.
- **What a Word document was hiding.** `rwlib/docx_text.py`, stdlib zip and XML only. `w:vanish`/`w:webHidden`/white-`w:color`/tiny-`w:sz` runs are judged with the safety band's directive rule, and a finding's `line` is the paragraph number. `--apply-safe` refuses the format.
- **Stylometric distance.** `rwlib/stylometry.py`, Burrows' Delta over `MARKER_WORDS`. Two sd floors keep three agreeing samples from licensing an infinite z, and `Z_CAP` applies to the average, deliberately not to the reported contributors: uncapped, one paragraph leaning on an unused marker scored z in the thirties and outvoted a hundred markers on the profile. `fingerprint()` computes its own leave-one-out band for the mean and full-set for the sd, because a pure leave-one-out band came out wider than the measurement it calibrates. Editing `MARKER_WORDS` changes what every stored fingerprint means (`SCHEMA_VERSION` exists for that), and `distance()` refuses a file from another schema. The module takes prose with markup already stripped: both call sites run `scan.strip_for_stats` first.
- **Which fingerprint a register measures against.** `stylometry.path_for(rules_path, register)` prefers `<name>.<register>.fingerprint.json`, falling back silently to the general one. `attain.py` prints which file it used because of that silence. The scope is read off the *filename*, and the stored `register` key is checked against it in `check_voices` and `voice_check.check_fingerprint`, since a file renamed by hand would otherwise measure one register while claiming another.
- **A fingerprint's measure block.** `measure_stats`, `sentence_shape`, `shape_target`, `measure_gaps` in `rwlib/stylometry.py` measure nothing themselves: every number comes from `scan.compute_stats`, passed in through `fingerprint(..., sample_measures=, sentence_lengths=)`. The shape is deciles, not raw lengths (which would ship the writer's prose verbatim) and not fixed buckets. `SCHEMA_VERSION = 2` is what an edit to any of it costs.
- **`voice-distance` never blocks a document.** It's the one voice finding with no rule and no rules-file requirement: a fingerprint is a separate artifact `scan.py` looks for via `stylometry.path_for`. It's P2 at the call site (not the voice's `default_priority`), so `default_priority: P0` cannot promote it, and it's deliberately absent from `fixes.py`. `voice-caricature` is the same: both are measurements about a document, capped at P2 forever, because that's what the `rabbit-scan` hook runs in a stranger's repository over a document nobody asked to convert. `attain.py --check` is the one place a number about an *edit* can fail: it exits 1 on `flat`/`regressed`, because that call named a profile and asked for a conversion.
- **What kind of document this is, and what slots it has.** `references/forms/`, one file per form, each naming the register it routes to. There is no third axis: a form *is* a register, so the set is a formality spine (`chat`, `informal`, `blog`, `formal`) plus four genre columns (`technical-blog`, `docs`, `linkedin`, `academic`) carrying tolerances no formality band captures. The ladder is data, under the "spine" key in `registers.json`. Two names were retired: "casual" collided with a voice persona of the same name, and "investor-email" was a document form posing as a strictness level. A form file supplies slots and never fills them: `check_form_files` in `scripts/validate.py` enforces that by requiring every quoted phrase to sit under `## Tells`, where the heading already says the phrases in it are proscribed. A default greeting in `email.md` would open every user's email the same way, the shared-fingerprint failure `false-positives.md` describes.
- **How a source is formatted in a reference entry.** `references/citations/`, checked by `check_citation_files` in `scripts/validate.py`. `CITATION_SLOT_RX` is the one carve-out to the forms-layer location rule, since MLA and Chicago quote titles inside their own patterns. Every style carries the same eleven source types (`CITATION_SOURCE_TYPES`). Citation style is orthogonal to form and register. Nothing in the engine validates whether a citation is real: that guardrail is the editor's.
- **Whether a rules file is a profile at all.** `rwlib/voice_check.py`, called by both `scripts/validate.py` and `voice-setup/scripts/build_voice.py --check`, so the two cannot disagree about what "valid" means. It checks structure only: template residue, the mechanic vocabulary (from `voices.MECHANIC_VALUES`), register names, ban entries naming no term, a `banned_regex` that doesn't match its own `example`. Whether a rule *fires* is a different question, answered in `build_voice.py` because it needs `scan.py`. `validate.py` exempts `TEMPLATE`, since the form is supposed to fail these checks.
- **Which voice profile applies, and why.** `rwlib.voices.resolve`: nearest `.rabbit-voice` (beside the document, then above the working directory), then `voices/ACTIVE`, then nothing. Each result names which. There is no fallback to a lone installed profile: the shipped `ACTIVE` is empty, so a fresh install never enforces this author's bans on a stranger's prose. `build_voice_command()` resolves the activation-command path from `__file__` across both checkout and packaged layouts. Four of the five clawhub bundles vendor `rwlib` without `build_voice.py` and get a skill-name note instead. This repository pins its own voice through a root `.rabbit-voice`, the same mechanism a consumer uses.
- **What priority a synthetic finding is.** `SYNTHETIC_PRIORITIES` in `rwlib/lexicon.py`, beside `SYNTHETIC_FINDING_IDS`. An id present in only one of the two sets raises rather than drifting. `hidden-unicode` is the one carve-out: the table names its P0 ceiling, and the space-like half raises at P2 at the call site.
- **How a voice profile becomes a system-prompt contract.** `rwlib/outputstyle.py`'s `render(rules, profile_md, voice_name=)` is pure, no filesystem, and lifts exactly two markdown sections verbatim, `## Voice in one line` and `## The three essentials` (both guaranteed by `TEMPLATE.md`). `signature_moves` is deliberately omitted: `voice-signature-underuse` is capped at P2 in the engine because a rule that tells an editor to *add* a move installs a tic, and a system prompt is a stronger push than any finding. A `banned_regex` carrying `max_allowed` renders as "at most N," not "never," and a `note` is cut to its first sentence.
- **What a number, a date, or a quotation is.** `rwlib/facts.py` canonicalizes before comparing: a date compares as ISO, a range is one token, `1,200` and `1200` are one number. Extraction is ordered and each pass eats its span, dates first (owned entirely by `dates()`). The date patterns live here rather than in `scan.py` because `verify.py` needs them and must not import `scan.py` (which lazily imports `verify`). Entities are report-only forever and never reach `ok`.
- **Where `rwlib` is, for something that is not Python.** `pyrightconfig.json` at the repo root, one execution environment per directory holding a `.py`, each naming `skills/rabbit-writes/scripts`. `check_import_paths` in `scripts/validate.py` keeps the two in sync: it fails when a directory's config gives no path to `rwlib` or its sibling `helpers`. `typeCheckingMode` is `off` on purpose: resolving `rwlib` is what unblocks inference on everything downstream, and stricter modes report 93-95 complaints about untyped stdlib scripts rather than real bugs.
- **Where a model server is, and whether this installation may talk to it.** `rwlib/endpoint.py`, one OpenAI-compatible client, no per-vendor branch. `resolve` mirrors `voices.resolve`: nearest `.rabbit-model`, then above the working directory, then `$RABBIT_MODEL_BASE_URL`, then nothing. There is no localhost fallback: a tool that silently discovers a server on 11434 silently ships a draft to whatever is listening there. Refuses a literal `api_key` in a committed config, plain `http` to anything but loopback without `allow_insecure`, and scrubs a key echoed back inside an error message. `estimate_tokens` is characters-over-three, deliberately pessimistic, because underestimating buys a truncated completion.
- **How a model is asked to rewrite something.** `rwlib/rewrite.py`. The unit of work is a finding, not a document. A tell sits in a sentence, so `plan` sends that sentence, its rule, and nothing else, which is why there's no chunking strategy and a 4k-context model is enough for a 10,000-word draft. `scan_fn`/`validate_fn` are injected (the same inversion `stylometry.fingerprint` uses), because `rwlib` reaching up to `scan.py`/`verify.py` would close an import loop. The gate: a candidate must keep every fact (`verify.validate`), must drop the flagged phrase, **and** must lower the total finding count. Checking only the id lets a model swap `delve into` for `robust` and pass, and checking only the phrase lets it swap the same pair from the other side. `run` refuses a document carrying a safety P0 *before the first request*, one step earlier than `run_apply_safe` refuses.
- **Reasoning models need thinking off, or the pass rate is zero.** Measured: Qwen3.5-0.8B-Q4_K_M on `llama-server` scored 0/15 with thinking on (every rejection `stopped at max_tokens`: the model spent its whole output budget on `reasoning_content`). Same model, same battery, with `THINKING_OFF` in the payload: 10/15 accepted, 8.58s down to 0.47s per passage. `endpoint.py` sends two spellings of the off-switch (llama.cpp reads `chat_template_kwargs`, hosted endpoints read `reasoning_effort`) and downgrades once, stickily, on a 400. `rewrite._THINK_RX` strips an inline reasoning block from `content` too, including an **unterminated** one, since a truncated thinking block has that shape. A `Truncated` error on a reply that carried one names the cause specifically rather than reporting an empty response.
- **A finding's `line` is a hint, and its `match` is sometimes not a string in the document.** `rewrite._locate` searches for the match and picks the occurrence nearest the reported line rather than trusting the number: a pattern anchored `(^|\n)` starts matching at the newline ending the *previous* line, so a finding on line 3 can report line 1. Two ids carry a match that's a description rather than a span (`uniformity` reports "sd/mean of sentence length", `tier2-cluster` reports its cluster words out of document order), and those anchor by line to their containing block instead. `BLOCK_IDS` names them.
- **`uniformity` is measured over the whole document, and is still reachable one paragraph at a time.** `rewrite.plan` fans it out to the prose blocks whose own sd/mean is below the floor, and the floor is passed in from `scan.BANDS["burstiness"][0]` rather than restated. `low-diversity` and `uniform-paragraphs` genuinely aren't per-block fixable and stay in `DOCUMENT_IDS`.

## Conventions & Gotchas

- **Importing `rwlib`**: Scripts insert `skills/rabbit-writes/scripts` into `sys.path` before importing. `scan.py`, `verify.py`, `readme_check.py`, and the corpus research scripts all bootstrap this way. Import via `from rwlib import ...`.
- **ASCII Only for Engine Source**: `test_every_invisible_logic_source_is_escape_only` rejects any codepoint over 0x7E in every engine `.py` file it walks, not only invisible ones (a visible `§` in a comment fails it too), except `markdown.py`, where the bar drops to invisible-only since its regexes spell curly quotes and dashes as themselves. Write non-ASCII as unicode escapes (` `), never literals: a shell heredoc passes a literal character through verbatim while the source line looks correct, which has broken a test fixture twice this way. After writing a fixture that way, grep the file for codepoints above 127. The walk is a list of roots, so a new script directory isn't held to the rule until added to it.
- **`verify.py` Blast Radius**: `verify.validate(...)["ok"]` decides whether `scan.py --apply-safe --write` writes at all. `run_apply_safe` refuses when it's false. A false positive is therefore not a noisy report, it's a fixer that silently stops working and reports itself as the problem. The fact check was calibrated over the 100-README corpus before being wired in, and `validate(text, fixes.apply(text, None)[0])` over the whole corpus is asserted rather than assumed.
- **Safety Band**: `rwlib/injection.py`'s two-axis rule: concealment and a directive in the same span is P0, either alone is a band lower. `references/injection.md` is the prose form. Never fixable (no id in `fixes.py`) and never suppressible (`suppress.apply` refuses the `safety` band outright, since a `rabbit-allow` comment lives inside the document an attacker controls), both asserted in `test_fixes.py`/`test_suppress.py`. A P0 halts rewrites, and `rewrite.run` refuses *before the first request* rather than after planning. It also scans raw text: the quoted-example exemption never reaches `citation-leak` or `curly-quote` (both carry `scan_raw`), which is why `references/patterns.md` publishes 5 P0s and `references/injection.md` publishes 9 P2s in `PROOF.md`. Quoting an attack to warn about it still reads as concealment plus directive.
- **Suppressions** (`rwlib/suppress.py`) are marked, never dropped: a suppressed finding keeps its place with a `suppressed` key, comes out of the priority counts, and prints under its own heading. `scan.scan(..., suppressions=False)` exists for `readme_check.py`, which merges both halves and runs one pass over the whole list. Running suppressions in both would fire a suppression naming a structure id twice.
- **`rwlib` never imports `scan.py` or `verify.py`**: `scan.py` imports `verify` lazily and `verify` imports `rwlib.facts`, so a module down here reaching back up closes the loop. `rewrite.run` takes `scan_fn`, `validate_fn`, and the burstiness floor as arguments for this reason.
- **Mode Contract Integrity**: `validate.py` pins `SKILL.md`'s mode table, its "a file path tells you where the text lives" line, and the absence of "minimum effective edit" from the guardrail section. It also runs `check_no_stale_skill_name`, a repo-wide sweep for a prose skill name merged away before release. Editing pinned lines in `SKILL.md`, or reintroducing that name, fails `scripts/validate.py`. The mechanics of both checks are in `.claude/docs/validate-internals.md`.
- **Tests reach `rwlib` via `from rwlib import x`**, never through `helpers.load_module`. That helper imports a file by path with no parent package, which fails for anything under `rwlib/` that imports a sibling (the relative import has no package, and the fallback has no `rwlib/` on `sys.path`). `helpers` puts `scripts/` on the path for exactly this.
- **`compute_stats` splits paragraphs on blank lines** (`scan.py:211`), so a bullet list is one paragraph. `avg paragraph sentences` on a list-heavy document measures list length, not prose. Inserting blank lines between bullets moves the number without changing anything a reader sees. Measure the non-list blocks separately before treating that number as a defect.
- **An output style's two frontmatter defaults are both wrong for this plugin, and both fail late.** `keep-coding-instructions` defaults to false, which drops Claude Code's own software-engineering instructions from the system prompt. A coding session turns into a writing session three turns before anyone notices why. `force-for-plugin: true` applies a style automatically whenever the plugin is enabled, which is backwards for a plugin that's always enabled while prose gets written only sometimes. `check_output_styles` requires the first and refuses the second, and `rwlib/outputstyle.py` is the one home for the key vocabulary both the shipped file and the generated one are checked against. A style also does not reach subagents (they run their own system prompt), so `rabbit-reads`' fan-out is unaffected and the voice contract still has to be in the subagent prompt directly.
- **A `PostToolUse` hook that exits 2 is talking to nobody.** The event is non-blocking. Exit 2 only prints stderr beside the tool result. `hookSpecificOutput.additionalContext` is the channel that actually reaches the model in the turn that wrote the file. `claude_hook.py` therefore exits 0 on every path, including unparseable stdin, a missing file, and a scanner that raised. The `except BaseException` at the bottom is load-bearing, since a prose linter that breaks a coding session gets uninstalled the same day. It's silent on a clean scan, a non-prose extension, and P2-only findings, for the reason the pre-commit hooks gate on P0 alone.
- **What makes a document a research paper, mechanically.** `sections.imrad_categories` is kept apart from `SECTION_KEYWORDS` because the two answer different questions (what a README section is for, versus whether a document is a paper at all). `registers.IMRAD_HEADINGS_REQUIRED` is 3, and the number is measured: at 2, a README carrying "Test Results" and "Limitations" reads as a paper (1 false positive in the 100-README corpus). At 3, it's 0, with recall against the 19 corpus papers' own JATS section titles at 17/19. Measure recall against those titles, never against this repository's own extracted texts, whose headings its own extractor wrote.
- **A register cell cannot muffle a fingerprint P0, so `vague-attribution` was narrowed in the rule instead.** It fired on "research suggests"/"studies show" in 6 of 19 corpus papers, where the phrase carries a citation the engine can't see, and a relaxed cell for it failed `test_no_p0_fingerprint_is_skipped_or_relaxed_anywhere` immediately. That test outranks a calibration result. The fix is a lookahead standing the rule down when a citation marker arrives before the sentence ends, scoped to the sentence rather than a character window (the marker sits 55-170 characters past the phrase and never inside 40). Took the corpus to 3/19 papers, 4 hits, README corpus unmoved at 0 P0.
- `python3 skills/rabbit-writes/scripts/rwlib/registers.py --write` was broken as a CLI for two releases and nothing noticed, because `validate.py` calls `doc_table()` through an import and never runs the command the docs give. The `except ImportError` fallback put `rwlib/` itself on `sys.path`, so `import markdown` succeeded and then `markdown.py`'s own `from .artifacts` failed one level down with the same error. It now inserts the directory *above* `rwlib` and imports the package.
- **Adding or renaming a register is data plus a sweep, and the sweep is all prose.** No register name is load-bearing in engine logic: `scan.py` derives everything from `registers.json`, and a missed rename in `voice_check.py`'s validated fields fails the build. What isn't caught automatically is the copies in docstrings, test fixtures, and `TEMPLATE.rules.json`, which is why `check_template_registers` validates the template's own register names too.
- **An id with a cell in every register has no register left to prove it in, so a one-sentence probe proves nothing.** All five mechanical STE ids carry a cell everywhere: one semicolon under the default register raises a finding the `blog` allowance of 2 then eats, and the test reads as a check that never ran. Read the allowance out of `registers.relax_table()` and repeat the unit past it, rather than hardcoding a count the next calibration moves.
- **Every cell in the matrix is exercised, from a table of trigger documents.** `TRIGGERS` in `tests/test_registers.py` holds one repeatable unit per finding id: a skip cell must silence a document that fires without it, and a relaxed cell must stay silent *at* its allowance and report past it. A cell that reports at the allowance is strict wearing a tolerance, and one that stays silent past it is a skip with an allowance written beside it (the confusion that left `curly-quote` unfirable in every register). A coverage test requires `TRIGGERS` to name every id the matrix mentions.
- `PROOF.md` carries two tables whose rows both start `` | `file.md` | ``: the self-scan table and the voice-band table. A regex rewrite of "the row for file X" hits both and silently replaces the voice-hit counts with stylometrics. Rebuild a table whole, or anchor on its column shape rather than the filename. Regenerate it off `--json` when files move or change (never just move it). Its own row counts its own words, so editing it moves the number you just wrote and takes an extra pass to reach a fixed point, and the reproduce command passes no `--voice-rules`, so its P0/P1/P2 columns are the no-voice numbers with the voice band in its own table further down.
- **The academic corpus regenerates, and only one of its three modes is safe to rerun.** `python3 scripts/academic-research/01_fetch_corpus.py` refetches the DOIs `docs/academic-corpus/manifest.json` already names and hash-checks each one. `--verify` does the hash check with no network, and `--discover` queries PLOS and pins a *new* paper set, silently moving every number measured against the old one. Then `02_measure.py` for per-register counts and `03_export.py`, not optional after a cell change: without it `PROOF.md` keeps quoting the old numbers. PLOS is the whole corpus because every article is CC BY 4.0, which the fetcher verifies before proceeding.
- **A term's hit count is not evidence about a register. Its document count is.** "holistic" raised 11 tier-1 hits across the academic corpus and appears in fewer than two of the nineteen papers. Exempting it on hit count alone would have hidden a real finding on the strength of one author's habit. `02_measure.py` reports docs and hits as separate columns for this reason.
- **Calibrate a new detector against `docs/readme-analysis/repos/*/README.md` before wiring it to anything.** Those are 100 real third-party documents, and a P0 there is a stranger's blocked commit. The safety band cost three regexes this way (`instead of editing`, an unanchored agent-noun rule, a bare `forget everything`), each a false positive nobody would have guessed. The corpus isn't the whole bar though: `forget` + a pronoun survived it and was narrowed later to the instruction shape, because in an HTML comment that reads as concealment plus directive. Assert the zero in a test rather than reporting it.
- **Calibrating a check that compares two documents,** where the corpus is 100 single documents with no pairs in it: four passes. Identity (`validate(text, text)` loses nothing, or the canonicalizer isn't idempotent). Null edit (the same through `fixes.apply`, the `--apply-safe` blast radius measured rather than argued about). One generated transform per carve-out, each required to produce zero violations. A planted corruption, required to be caught. **Apply reformat transforms outside quoted spans.** Mutating text inside a quotation tests an edit the skill forbids, and protecting quotes by construction makes the result circular.
- The labeled corpus in `docs/detector-corpus/` is empty and the harness around it is not. `scripts/detector-corpus/score.py` publishes a per-register false-positive rate with a Wilson interval the moment somebody populates it. Until then, calibration rests on two hand-written samples, which `PROOF.md` says plainly.
