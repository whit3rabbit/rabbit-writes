# affaan-m/ECC — qualitative note

This README is dominated by promotional and structural apparatus before it reaches substance: a hero image, a 12-language link bar, four rows of badges (Discord, website, GitHub App, license, stars, forks, contributors, installs, npm downloads, language chips), a security warning callout, a sponsor table, and a sponsor logo strip all appear before the first `#` heading — a real "what is this" description doesn't start until line 107. Once it gets going, the install section is a good example of an anti-pattern: dozens of nested `<details>` blocks covering guided/manual/per-harness/low-context/component-level/reset paths, each with its own caveats ("Do not stack install methods," "If you choose this path, stop there"), which signals an install process complicated enough to need a decision tree rather than a quickstart. The "Why Choose ECC?" two-column comparison table ("Without a system" vs "With ECC") is a genuinely effective technique, though, compressing the value proposition into scannable contrasts that the surrounding prose doesn't achieve as clearly. The tone throughout is dense and caveat-heavy, reading more like exhaustive release/support documentation than an onboarding pitch, and the changelog for prior versions is embedded in full inside the README itself rather than linked out.

**Quotes:**
- "Optimize the context window. Persist everything else." — pull-quote summarizing ECC's approach
- "**Do not stack install methods.** Installing ECC twice into the same harness can duplicate skills, commands, hooks, or configuration" — from the install-path warnings
